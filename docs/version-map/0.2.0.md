# 0.2.0: ARGUS Studio — lanes in, data products out, every AI step on the timeline

**Goal:** one screen per project, laid out like a broadcast studio. A person makes a lane, drops files or
video on it, picks data products, and watches Meta's models read each file on a playable timeline.
Visitors watch the same Studio as a replay on `/explore`, with no sign-up and no model calls.

**Status:** Released 2026-10-29 as `v0.2.0`. The breadth plan that was 0.2.0 (RTSP, MQTT, scheduled
polling, fuzzy matching) moved to [0.3.0](0.3.0.md), and the video people census to [0.4.0](0.4.0.md).

## What ships

| Area | In 0.2.0 |
| --- | --- |
| Studio | `/studio/[id]`: lanes on the left, preview in the middle, data products on the right, timeline at the bottom. Setup opens as Studio windows, not pages. The old `/dashboard` is gone |
| Lanes | The lane comes first: every file, video, feed or sensor goes in through one. The AI suggests lanes for the chosen products and links them. Files are dropped straight onto a lane |
| Video | Frames sampled in the browser with `<video>` and canvas (no ffmpeg), sent to the server and traced |
| Models | Muse Spark names what is in a picture. SAM 3.1 locates each object as an `object_mask` Observation with a real outline. A model registry (`src/lib/models.ts`) says which model does which job |
| Products | New: Object footprint. Density heatmap uses real positions from SAM. Persona perception and a private body log |
| Timeline | Simple, Lane steps and Everything modes. Dots for files, product markers, play and skip quiet. It starts at the first activity and ends at the last data, not today |
| Observatory | Every model call, code step and tool call is recorded with `traced()` and shown in the Studio |
| Projects | `/projects` is for reading data products, full screen and presentation-like. Setup lives in Studio |
| Ask ARGUS | One chat across projects with `@project` mentions |
| Explore | A shared project replays as a read-only Studio. Media shows only if the owner opts in; body photos never do |
| Docs | `/docs` with a real guide, FAQ and screenshots |

- [x] Three real demo projects replay on `/explore`: a crane build, a roundabout drone video and a body log

- [ ] The GitHub Release for `v0.2.0` exists with the changelog notes

## Not in 0.2.0

- Vehicle traffic dashboard and Road safety event feed still have no tracking behind them, so they
  compute nothing on video. They need a per-frame vehicle count first.
- AI-engineered products (a model proposes a manifest, code validates it) wait for a later version.
- Alerts (user rules checked by code, explained by the AI) were discussed, not built.
