# 0.3.0: breadth — more sources, scheduled polling, fuzzy matching

**Goal:** a person connects a real camera or MQTT sensor, polling runs on a schedule without a
visitor, and observations from differently-named sources fuse to the same asset with human
confirmation. Everything still becomes an Observation.

**Status:** Planning. Unchecked boxes in [0.1.0](0.1.0.md) carry over (0.2.0 shipped ARGUS Studio instead) and must be closed or
explicitly deferred before 0.3.0 freezes.

## What ships

| Area | In 0.3.0 |
| --- | --- |
| Sources | Real camera / RTSP connector (frame sampling dial, reconnect), MQTT broker connector behind the same interface as the simulated vibration sensor, database connector, REST-poller connector |
| Polling | Scheduled `/api/jobs/drain` (cron or QStash) so polled sources run without a visitor |
| Fusion | Fuzzy and embedding entity matching; unmatched observations queue for human confirmation before merging into an asset |
| Agents | Unmatched-entity review joins the pending-alert review flow; no new agent roles |
| Products | No new products; existing 6 work unchanged over the new sources |
| Surfaces | Source Hub shows health and last-seen for the new connectors; unmatched-entity queue UI |
| Engineering | Same gates: `bun test` on PGlite, 95% gate, CI green on every push |

## Exit criteria

Tag `v0.3.0` only when every box is checked.

### Carryover from 0.1.0 (close or explicitly defer)

- [ ] Route tests with a faked session (`/api/uploads`, `/api/capture/frame`, `/api/flows/**`, CSV exports; 401/404 cases)
- [ ] Server-action tests for `actions.ts`, `pipeline-actions.ts`, `flow-actions.ts`
- [ ] MCP server: list tools, one call through `ops` with an API key
- [ ] Browser smoke test (Playwright under Bun) of the main story, running in CI
- [ ] The Bridge story runs live against the Meta API, with a recorded fallback clip
- [ ] With `META_API_KEY` unset, the app says plainly the model is not configured
- [ ] Every product page shows sample-data state with no sources, live state when connected
- [ ] `/design` has a surface for every widget in `src/widgets/registry.tsx`
- [ ] Production deploy documented end to end; `BETTER_AUTH_URL` set
- [ ] Scheduler calls `/api/jobs/drain` — this becomes required, not optional, in 0.3.0
- [ ] Secrets checked; package renamed `argus-preview` → `argus` (or deferred with a reason)

### New scope

- [ ] RTSP connector ingests frames from a real stream; sampling dial bounds Meta API cost; reconnects survive a dropped stream
- [ ] MQTT connector subscribes to a broker topic and writes Observations through the same interface as the simulator
- [ ] Database connector (one engine first) and REST-poller connector (configurable URL, schedule, mapper) both write Observations
- [ ] Every new connector has a Zod config schema, a manifest entry, and tests that keep the coverage gate green
- [ ] Fuzzy match proposes asset merges; nothing merges without human confirmation; every merge keeps provenance
- [ ] Scheduled polling runs in CI or staging for 24h without manual visits before the freeze

## Not in 0.3.0 (cut list)

Moved to 0.5.0 or later (0.4.0 is the video people census). Adding any of these unfreezes the release.

- PostGIS spatial joins, map products, projection from image to map
- Data Fusion Canvas and a product-builder UI beyond flows
- Any of the 26 roadmap products
- Multi-tenant teams and roles
- Stream processor, watermarks, signed lineage

## Risks

| Risk | Mitigation |
| --- | --- |
| Real streams cost more (bandwidth, Meta API) | Sampling dial, frame caps, recorded fallback clip |
| Fuzzy matching merges the wrong assets | Human confirmation required; merges are reversible and provenanced |
| Broker and database credentials in scope | Server-side only, never `NEXT_PUBLIC_*`; secrets check in exit criteria |
| Scope creep from the sources list | Anything not in scope stays marked "Roadmap"; the cut list freezes the release |

## Suggested order

1. Close the 0.1.0 carryover first: route and server-action tests, then the browser smoke test.
2. Ship scheduled polling — every other 0.3.0 connector depends on it.
3. MQTT connector (same interface as the simulator), then RTSP, then database and REST-poller.
4. Fuzzy matching with the confirmation queue.
5. Product and operations items, then freeze.
6. Release checklist.
