# 0.4.0: video people census — count, cut out and replay

**Goal:** a showcase story for the hackathon (`docs/HACKATHON.md`). We upload a video and ARGUS tells
how many distinct people appear in it. For each person it shows a cut-out, the frames
and timestamps they appear in, and the frame itself with that person highlighted. The whole analysis
can be replayed later from what was stored, with **zero** new model requests. Visitors watch that
replay on `/explore`: every Meta model step, what it proposed, and what code computed from it.

The test video can be a MrBeast episode, analyzed privately. The public replay needs footage we have
the right to publish (see Privacy and rights).

**Status:** Planning. Starts after `v0.3.0` ships. It reuses 0.3.0's embedding matching and its
human-confirmation queue to merge "the same person seen in two shots".

## The capability, in one line

Video file in → a roster of distinct people (anonymous: "Person 1", "Person 2", …), each with
cut-outs, appearance ranges and evidence frames → a replay that costs nothing.

It fits the project goal: a new source (video file), new Observations (frames, detections, masks),
fusion (tracks joined into people), a new product manifest and new widgets.

## Can Meta do it?

| Step | Meta model | Notes |
| --- | --- | --- |
| Count people in a frame, describe the scene | The vision chat model ARGUS already uses (`chatModel()` in `src/lib/meta.ts`) | Proposes counts only. Code never treats an LLM number as a measurement. |
| Cut each person out, keep their identity across frames | **SAM 3.1** (Segment Anything), prompted with the text "person" | Reported in March 2026 as available on the Meta Model API. One call returns boxes, masks and per-object identities across a frame sequence. Up to 16 objects per pass. **Must be confirmed in the spike (step 1).** |
| Same person in two different shots? | Embeddings of each cut-out, plus the vision model as a tie-breaker | SAM keeps identity inside one continuous shot. Hard cuts break tracks, and MrBeast videos cut every few seconds, so shots must be joined afterwards. That join is 0.3.0's embedding matching. |

If SAM 3.1 turns out not to be on the API key ARGUS has, the fallback order is:
1. A hosted SAM 3 endpoint behind the same `segmentPeople()` interface.
2. A GPU worker running the open SAM 3.1 checkpoints.

Browser (WebGPU) SAM is not a fallback for 0.4.0. No official browser build was found.

## How it flows (Observation first, per `AGENTS.md`)

1. **Source, in the browser** (`src/sources/video-file/`):
   - The video never leaves the person's machine. The browser decodes it (`<video>` + canvas, or
     WebCodecs).
   - It finds shot cuts deterministically from frame differences, and samples frames per shot. The
     tune dial sets the rate, and the cost estimate comes from `estimate()` in `src/lib/tune.ts`.
   - It uploads each shot as a short sequence of JPEG frames.
   - Writes `video_frame` Observations: video id, shot id, timestamp, frame key.
2. **Reasoning steps** (`src/lib/agents/orchestrator.ts`, typed input and output):
   - `countPeople(frame)` → `people_count` Observations (the existing type, now with `video` and `t`).
   - `segmentPeople(shot)` → `person_mask` Observations: shot-local track id, box, mask key, score,
     timestamp.
   - `embedPerson(mask)` → an embedding stored on the mask Observation.
   - Every model response is stored raw, with the model id and a hash of the request.
3. **Fusion** (`src/lib/fusion.ts`, deterministic):
   - Shot tracks are joined into people by embedding similarity.
   - Merges above the high threshold are automatic. Merges in the grey zone go to the 0.3.0
     confirmation queue. Nothing below the low threshold merges.
   - Output: `person` entities, each with its tracks, appearance ranges, a best cut-out (the largest,
     sharpest mask) and provenance.
   - **The count is computed by code** from the confirmed people, never taken from a model.
4. **Product manifest** `video-people-census` in `src/products/manifests/supported.ts`:
   - Fields: person id, first seen, last seen, screen time, appearances, cut-out key.
   - It reports the count with a range (confirmed people, plus people still awaiting confirmation).
5. **Widgets** (`src/widgets/library/` + `registry.tsx`, each previewed in `/design` first):
   - `people-roster`: a grid of cut-outs, the count, and screen time per person.
   - `appearance-timeline`: one lane per person across the video's length. Clicking a mark opens
     the frame.
   - `frame-viewer`: the frame with that person's mask outlined, the other people dimmed, and the
     timestamp.
   - States: empty, analyzing (frames processed of total), awaiting confirmation, done, error.
6. **Replay with no API calls:**
   - Replay reads only stored Observations, frames and masks. It plays the video's timeline, and the
     roster fills in as people are found, exactly as the analysis did.
   - Changing a merge threshold and recomputing the roster is also free, because fusion is code over
     stored data.
   - Enforced in code: replay modules never import `@/lib/meta`. A test asserts zero model calls and
     zero `fetch` during replay.

## Privacy and rights (new privacy level)

Today's people products are `no-person-identification`: aggregate counts only. This product keeps
per-person records inside one video, so it needs a stricter, explicit level, `anonymous-within-video`:

- People are numbered, never named. No face recognition, no matching against any outside identity.
- People are never linked across videos or projects. Embeddings are scoped to one video and deleted
  with it.
- Cut-outs and frames stay private by default. The `/explore` share leaves them out (counts and
  timelines only), and the share dialog says so.
- Upload asks the person to confirm they have the right to analyze the video. Copyrighted episodes
  are analyzed privately, never republished.
- The public showcase replay uses our own or openly licensed footage. Only then may its cut-outs and
  frames appear on `/explore`, and the owner turns that on per video.

## What ships

| Area | In 0.4.0 |
| --- | --- |
| Sources | Video file, processed in the browser: shot detection, per-shot frame sampling, resumable upload of frames only |
| Agents | `countPeople`, `segmentPeople` (SAM 3.1), `embedPerson`, and the vision model as a tie-breaker for grey-zone merges |
| Fusion | Shot tracks → people, with embedding matching and the 0.3.0 confirmation queue |
| Products | `video-people-census` (new). `people-count` also works on video frames. |
| Widgets | `people-roster`, `appearance-timeline`, `frame-viewer` |
| Surfaces | Video analysis page with live progress, the confirmation queue for person merges, and the replay player |
| Engineering | Same gates. Tests for every new step, plus a "replay makes zero model calls" test. |

## Exit criteria

### Spike first (before any other work)
- [ ] Confirm SAM 3.1 on the Meta API with ARGUS's key: request shape, limits, price, max frames per call
- [ ] Run one 10-minute test video end to end by hand. Record frames sent, calls made, cost and time.
- [ ] Decide the default sample rate and the frame cap from those numbers

### New scope
- [ ] A 15-minute 1080p video uploads with only frames leaving the browser, and survives a page reload (resumable)
- [ ] Shot detection is deterministic and tested on fixture frames
- [ ] Every model step writes Observations with the raw response, model id and request hash
- [ ] Fusion joins tracks into people. Grey-zone merges wait for a human. The count is computed, with a range.
- [ ] Roster, timeline and frame viewer are in `/design` with every state, then wired into the page
- [ ] Replay plays a finished analysis with zero model calls and zero network requests to Meta (tested)
- [ ] Re-running fusion with a new threshold changes the roster without any model call (tested)
- [ ] Privacy level `anonymous-within-video` enforced: no names, no cross-video links, nothing private on `/explore`
- [ ] Cost shown before analysis starts (frames × level price), with a hard cap the person sets

### Quality gate and release
- [ ] Lint, typecheck, `test:coverage` (95% gate) and build, all green in CI
- [ ] `CHANGELOG.md` Unreleased reads well
- [ ] `bun run release 0.4.0` and a maintainer tags it, then the GitHub Release exists

## Not in 0.4.0 (cut list)

- Live streams. File upload only; RTSP from 0.3.0 can feed this later.
- Naming people, face recognition, or linking people across videos. Never planned.
- Tracking huge crowds person by person. Background crowds are counted per frame
  (`people_count`), and the roster covers people large enough to segment.
- Audio and speaker diarization
- PostGIS, map products and the Data Fusion Canvas move to 0.5.0

## Risks

| Risk | Mitigation |
| --- | --- |
| SAM 3.1 is not on our API key, or is priced too high | Spike first. `segmentPeople()` hides the provider. Fall back to a hosted SAM 3 or a GPU worker. |
| Cost of a long video | Shot-aware sampling, a cost preview, a hard cap, and replay instead of re-analysis |
| Fast cuts and costume changes split one person into two | Grey-zone merges go to a human. The count shows a range until they are confirmed. |
| One person merged with another | High auto-merge threshold. Merges are reversible and provenanced. |
| Privacy of people in the video | `anonymous-within-video` level, private cut-outs, a rights confirmation on upload |
| Browser memory on long 4K files | Decode by seeking, never load the whole file. Downscale frames before upload. |

## Suggested order

1. Spike: SAM 3.1 on the Meta API, cost and limits.
2. Browser source: decode, shot detection, sampling, resumable frame upload, `video_frame` Observations.
3. `countPeople` and `segmentPeople`, with stored raw responses.
4. Embeddings and fusion into people, using the 0.3.0 confirmation queue.
5. Widgets in `/design`, then the product manifest and the page.
6. Replay with the zero-call test.
7. Privacy level, cost cap, then freeze and release.
